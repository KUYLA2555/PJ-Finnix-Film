# ตรวจงานด้วยเบราว์เซอร์อัตโนมัติ — ย้ายมาจาก CLAUDE.md (3 ต.ค. 2569 · /doctor)

**ตรวจงานด้วยเบราว์เซอร์อัตโนมัติในเครื่องนี้ไม่น่าเชื่อถือ — `requestAnimationFrame` ไม่เดินเลย**
วัดแล้วพบว่า rAF loop เปล่าๆ ที่ไม่เกี่ยวกับ CSS ของหน้า วนไม่ครบ 1 วินาทีใน 45 วินาที = **เฟรมเรตแทบเป็นศูนย์ในแท็บที่ถูกสั่งงานอัตโนมัติ**
ผลที่ตามมาคือ **ตัวนับ `.cnt` ค้างกลางทาง** (เห็น `0.3 / 0.6` แทนที่จะจบที่ `3 / 7`) และ **สั่ง screenshot ผ่าน CDP ค้างครบ 30 วินาที** — ทั้งสองอย่างเป็นอาการของสาเหตุเดียวกัน **ไม่ใช่บั๊กของโค้ดตัวนับ**
การฉีด `backdrop-filter:none` ช่วยให้แคปหน้าจอผ่านได้บ่อยขึ้น จึงควรทำก่อนตรวจเสมอ **แต่ไม่ได้แก้เรื่อง rAF** — v1.8 เคยสรุปว่า `.filtered` ใน hero เป็นตัวการ **ซึ่งพิสูจน์แล้วว่าไม่ใช่**
**ตัวนับกับ motion ที่ผูกกับ scroll ต้องเปิดดูด้วยตาในเบราว์เซอร์จริงเท่านั้น อย่าตัดสินจากผลอัตโนมัติ**

**หน้าต่างเบราว์เซอร์ในเครื่องนี้ย่อต่ำกว่า 1920px ไม่ได้ — แต่ `<iframe>` วัดแทนได้ (v3.1)**
สร้าง iframe กว้างตามต้องการชี้ไปหน้าเดียวกัน iframe มี viewport ของตัวเอง media query ข้างในจึงคำนวณตามความกว้างนั้นจริง และเป็น same-origin จึงอ่าน `getComputedStyle` / `getBoundingClientRect` ข้ามเข้าไปได้ · **ใช้ยืนยันจำนวนคอลัมน์ · ความกว้างช่อง · การล้นแนวนอน ที่ 375px ได้จริง ไม่ใช่การจำลอง**
**อีกสองอย่างที่ยังพังในแท็บอัตโนมัติ นอกจาก rAF** — **transition/animation ค้างที่ค่าเริ่มต้น** ต้องฉีด `transition:none!important` ก่อนอ่าน computed style ถึงได้ค่าปลายทางจริง · **`MediaQueryList` `change` ไม่ยิงเลย แม้แต่ listener ที่วางเองสดๆ** (แปลว่า `change` listener ของ drawer ตั้งแต่ v1.5 ก็ไม่เคยถูกตรวจจริง) — ทดสอบสาขาที่ผูกกับเบรกพอยต์ด้วยการ**โหลด iframe ใหม่ที่ความกว้างเป้าหมาย**แทน
**ที่ยังต้องเปิดดูด้วยตาคนเท่านั้น** — ตัวนับ `.cnt` · ความสวยงามจริงที่ 375px · การกดด้วยนิ้ว (ค้างข้อ 13) · เวลารายงานเกณฑ์ข้อ 7 ให้เขียนว่าวัดอะไรไปแล้วบ้าง อย่าเหมารวมว่าผ่าน
