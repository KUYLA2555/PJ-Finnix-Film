# tools/ — เครื่องมือของโปรเจกต์

โฟลเดอร์นี้เพิ่มใน v3.3 · ก่อนหน้านั้น repo ไม่มีไฟล์สคริปต์เลยโดยตั้งใจ
**ของในนี้ไม่ใช่ build system** — เว็บทำงานได้ครบโดยไม่ต้องรันอะไรทั้งสิ้น ลบโฟลเดอร์นี้ทิ้งเว็บก็ยังเหมือนเดิม

| ไฟล์ | ทำอะไร |
|---|---|
| `sync-shared.py` | ทำให้ "ของร่วม" ของทั้ง 6 หน้าตรงกันเสมอ |
| `shared/*.txt` | **ฉบับจริง** ของแต่ละบริเวณที่ใช้ร่วมกัน — แก้ที่นี่ที่เดียว |

## ปัญหาที่มันแก้

ข้อ 9 ของบรีฟบังคับว่าหนึ่งหน้าต้องจบในไฟล์เดียว CSS/JS จึงแยกออกไปเป็นไฟล์ร่วมไม่ได้
ผลคือ tokens · nav · drawer · footer · noscript ถูกคัดลอกไว้ **6 ชุด** แก้ทีหนึ่งต้องแก้ 6 จุด

ที่ผ่านมามันไถลออกจากกันเรื่อยๆ จนต้องไล่ตามแก้แทบทุกเวอร์ชัน (v2.8 · v2.9 · v3.0 · v3.1 ต่างมีงานไล่จับ drift ทั้งนั้น)
ตอนไล่ครั้งสุดท้ายพบว่า **กฎ CSS เหมือนกันหมดแล้ว ที่ต่างคือคอมเมนต์** ซึ่งเป็นร่องรอยการคัดลอกข้ามไฟล์ล้วนๆ

## ทำไมไม่แยกเป็นไฟล์ CSS ร่วมไปเลย

`<link rel="stylesheet" href="assets/base.css">` จะประหยัดได้จริง ~31 KB (31% ของ CSS ทั้งหมด)
**แต่ชนข้อ 9 ตรงตัว** ซึ่งอยู่ในหมวด "กฎที่ละเมิดแล้วงานไม่ผ่าน" — ต้องให้ผู้สั่งงานยกเส้นเองก่อน

วิธีนี้จึงเลือกแก้ **ต้นทุนการดูแล** (6 จุด → 1 จุด) แทน **ขนาดไฟล์**
ไฟล์ที่ขึ้นเซิร์ฟเวอร์ยังเป็นไฟล์เดียวจบต่อหนึ่งหน้าเหมือนเดิมทุกประการ

## วิธีใช้

รันจาก root ของ repo

```bash
python tools/sync-shared.py           # ตรวจอย่างเดียว — ต่างเมื่อไหร่ exit 1
python tools/sync-shared.py --write   # เขียนฉบับจริงลงทั้ง 6 ไฟล์
python tools/sync-shared.py --pull index.html   # ดึงจากไฟล์นั้นขึ้นเป็นฉบับจริง
```

**ลำดับที่ตั้งใจให้ใช้**

1. แก้ของร่วม — จะแก้ที่ `tools/shared/` ตรงๆ หรือแก้ในหน้าเว็บหน้าใดหน้าหนึ่งก็ได้
2. ถ้าแก้ในหน้าเว็บ ให้ `--pull <ไฟล์นั้น>` ขึ้นเป็นฉบับจริงก่อน
3. `--write` แล้วรัน `python tools/sync-shared.py` ยืนยันว่าได้ `ไม่ตรง 0`
4. ตรวจเกณฑ์ 9 ข้อตามปกติ แล้วบันทึกลง CHANGELOG

## บริเวณที่ดูแลอยู่ 9 จุด

| ชื่อ | คือ |
|---|---|
| `TOKENS` | `:root{}` — สี ระยะ ฟอนต์ easing |
| `NAV_CSS` · `DRAWER_CSS` · `FOOTER_CSS` | CSS ของ nav · เมนูมือถือ · footer |
| `NOSCRIPT` | บล็อกสำรองเมื่อ JS ไม่ทำงาน |
| `NAV_HTML` · `DRAWER_HTML` · `FOOTER_HTML` | markup ของสามส่วนนั้น |
| `JS_NAV` | JS ของ nav กับ drawer |

ในหน้าเว็บ แต่ละบริเวณถูกคร่อมด้วย `@shared:ชื่อ` กับ `@end:ชื่อ`
**ห้ามแก้เนื้อหาระหว่างเครื่องหมายโดยตรงแล้วลืม `--pull`** — `--write` รอบหน้าจะเขียนทับ

## ข้อควรระวัง

- **`@CUR:ชื่อหน้า@` ใน `NAV_HTML` / `DRAWER_HTML`** คือที่ที่ `aria-current="page"` จะไปลง สคริปต์ใส่ให้เองตามชื่อไฟล์ **อย่าพิมพ์ `aria-current` ลงไปในฉบับจริงเอง**
- **ขอบเขตของบริเวณห้ามซ้อนกัน** — ตอนวางเครื่องหมายครั้งแรกเคยพลาดจนเครื่องหมายเปิดของ `DRAWER_CSS` ไปอยู่ในบริเวณของ `NAV_CSS` แล้วถูก `--write` เขียนทับหายไป
- **`tools/shared/` เก็บเป็น LF ส่วนหน้าเว็บเป็น CRLF** สคริปต์แปลงให้ตอนอ่าน/เขียน · `--write` มีตัวนับ CR เดี่ยวกันพลาดไว้แล้ว ถ้าเจอจะ exit 1
- โฟลเดอร์นี้ **ห้ามขึ้นเซิร์ฟเวอร์จริง** เป็นของใช้ตอนพัฒนาเท่านั้น
